The inventory system keeps the list of spare parts, how many of each every site needs, who owns the ones on hand, and where they physically are. It also holds the purchase order process, which has its own guide.

Who can change things

Everyone who is signed in can see the Master List, Required Inventory, Ownership, Physical Location and History. Only people with the Inventory role can change any of them. If you do not have it you will not see the edit buttons. Ask an admin if you need it.

The ideas that explain everything else

  • Owned and where it is are two separate numbers. Ownership says which site's count a unit belongs to. Physical Location says where the unit is sitting. For every part the two totals always match; the system refuses any change that would break that.
  • Places a unit can be: Oshawa, the Barn, the Office, or a site's own shelf.
  • A site's own shelf can only hold parts that site owns. To move a part from one site's shelf to another's, transfer ownership first (Stock Transfer), which moves the units with it.
  • Some sites keep no parts on a shelf of their own (Firelight Operations and Firelight Solar). They still own parts, which are kept in Oshawa, the Barn or the Office, and they have no shelf column on Physical Location.
  • Stock is never edited directly. Each change goes through a check that applies the rules and writes a line in History, so there is always a record of who did what and why. A reason is required for every change.
  • Yellow numbers are spares on issued purchase orders that have not been received yet. They are counted so you can see what is coming, but they are not on the shelf until the requisitioner marks the PO's parts Received.
Words

In this system a Site is a solar site company (SunE Alfred LP and so on). A Location is a place within a site that has several (Firelight's rooftops). A Project is the top layer (Regular O&M, Repower - Phase 1, Repower - Phase 2). The ticket system calls a site a "project", which is a different thing.

1 Master List

Everyone can view and exportInventory edits

One row per part. Columns: GCS P/N, Pic (a reference picture), Data (datasheet), Manufacturer, Mfr Part #, Description, Category, Used By (the sites that require it) and Last Cost. Filter any column, and use Clear filters to start again.

Descriptions have three lines

  1. What it is, a generic word (Relay, Contactor, Circuit Breaker, Fuse…).
  2. Model and ratings.
  3. Anything else (optional).

They are shown as three blocks: what it is in bold, then the model and rating, then the rest in grey. An older one-line description shows as plain text.

Inventory
  • Edit List makes the rows editable. Edit a description in its three-line box. Press Delete on a row to remove a part, and save.
  • Picture: in edit mode press Attach or Replace. The picture is shrunk automatically. Anyone can click the picture icon to see it.
  • Datasheet: in edit mode each part has PDF (upload), Link (paste an address) and ✕ (remove). A new part must be saved before you can attach a picture or datasheet. Anyone can click the document icon to open it.
  • Import List: a CSV with columns GCS P/N, Mfr Part #, Manufacturer, Category, Description. A row with an existing GCS P/N updates that part; a row with the P/N left blank adds a new part. A column your file does not have is left alone, so a file with only GCS P/N and Description changes only descriptions. You see a preview ("Add new" / "Update", unchanged cells marked) before anything is saved. Put multi-line descriptions in a quoted cell.
  • Export List downloads the list as a CSV that Import can read back.
  • Change History shows every change ever made to the Master List (who, when, old and new values) with filters.

The Part ID column is no longer shown. New parts still get one generated automatically.

2 Required Inventory

Inventory edits

Pick a Site. The table lists the parts that site requires: GCS P/N, Part ID, Manufacturer, Description, Target Stock (how many it should keep) and Shared.

  • Shared means the target is a pool several sites draw on, not each site's own. When totals are added up, shared targets count once (the largest) rather than being added together.
  • Edit List (Inventory role) lets you tick parts on or off, set target stock and the Shared marks, with a search box to narrow the list. Press Save Changes.
  • Why it matters: a site can only order a part on a PO (as a spare or used part) if the part is on its Required Inventory list, and only sites with the part on their list can receive it in a transfer.

3 Inventory On Hand: Ownership

Everyone can viewInventory changes counts

A grid of parts down the side and sites across the top, showing how many each site owns, with the target stock and the total owned. Choose a site in the dropdown to see just that one, and Export CSV to download it. Click a part to jump to where it physically is.

Changing a count

Inventory

Press Update Count. You have three ways to change ownership.

  1. Individual Adjustment. Press Individual Adjustment, type new numbers into the cells (search to narrow the list), write a reason, and press Save Adjustment. A window then asks where the units are, one row per changed count: for an increase, where the extra units are put; for a decrease, where they are taken from. Choose a location on every row (there is a Set every row to shortcut), then Confirm & Save. Places that do not hold enough units are greyed out, and Automatic takes from the site's own shelf first, then Oshawa, the Barn, then the Office. A site with no shelf of its own cannot be given a shelf location.
  2. Upload a count. A CSV with columns GCS P/N, Site and Quantity. Every row replaces that part's count at that site, and you see a preview (previous and new) before confirming. One bad row cancels the whole upload. Extra units go on the site's own shelf (Oshawa for a site without one); removed units come off its shelf first, then Oshawa, the Barn, then the Office. Export Current Counts (CSV) gives you a starting file.
  3. Stock Transfer. Moves ownership from one site to another and moves the units with it (see below).

Stock Transfer

Inventory
  • Press Stock Transfer, choose From and To sites, type a reason, and say where the units are being taken from and where they end up (the sender's own shelf, Oshawa, Barn or Office; the receiver's own shelf only if it has one). Type a quantity on the part's row and press Transfer.
  • The move is treated as having already happened, so the owner and the location change together.
  • The receiving site must have the part on its Required Inventory list, or the Transfer button is off.
  • Each transfer also creates a PO from the sender to the receiver, using the part's Last Cost as the price. It starts at the Requested stage and is taken through approval, issue, receiving and closing by hand like any other PO. Its number is shown on the History entry and in the confirmation message.

4 Inventory On Hand: Physical Location

Everyone can viewInventory moves and uses parts

A grid of parts against places: Oshawa, Barn, Office, then each site that has a shelf of its own, with a total. There are three ways to narrow it, and they work together:

  • The search box ("Search part number, description, maker…"). Every word you type must appear in the part number, Part ID, description, manufacturer or manufacturer part number. It also works while you are moving or using parts.
  • The location dropdown shows only parts that have units in that place. Export CSV follows it, so with Oshawa chosen you export just what is in Oshawa.
  • The GCS P/N dropdown in the heading.
Inventory

Update Location (ownership does not change)

  • Type a reason (needed first). On the part's row choose From (where the units are now, with the count), To, a Qty, and press Move.
  • A site's shelf can only receive units that site owns. Options that cannot work are greyed with the reason, for example (transfer ownership first), (owns none off-site) or (no site).
  • Parts cannot go straight from one site's shelf to another's. Use Stock Transfer for that.

Record Part Use (the part was used)

  • Type a reason, choose Used from (the place), and Whose count it comes from (automatic if it is a site's shelf; if it is Oshawa, the Barn or the Office, choose which owner), a quantity, and press Record Use. The units leave the place and that owner's count.

While you are moving or recording use, the yellow "on order" numbers are hidden, because these actions work on real stock only.

5 Inventory On Hand: History

Every stock change, one entry each: who, when, the reason, and for each part the before and after, shown as Owned by … or Location: …. Filter by type (adjustment, count, transfer, use, PO received, location move, opening balance) and press Refresh. History cannot be edited. The entry for a transfer names the PO that was created; the entry for receiving names the PO and vendor.

6 How stock goes up when a PO arrives

  • Stock rises only when the requisitioner sets the PO's Parts Status to Received. Issuing the PO does not add stock, and neither does matching an invoice.
  • If the PO has spare parts, a window asks where the units are (Oshawa, Barn, Office, or the site's own shelf if it has one). They are added to that site's count at that place, once.
  • Used-immediately parts, consumables and services never add to stock.
  • A pre-paid PO with spare parts must still be set to Received before it can be closed.

7 The other tabs, briefly

  • Suggestions. Choose the type, the page it concerns, write your suggestion, and send it. You see its status and any reply on your own list. Admins see everyone's, with a New badge, a status (New, Looking at it, Planned, Done, Won't do), a reply box and an export.
  • Budget (admin and accounting). Pick the Project and Year. Each site has its Budget, Issued POs, Actual Invoiced, To be invoiced and Remaining, by category (a Remaining summary view shows % used). Click a figure to list the POs behind it. Only an admin can use Edit budget.
  • Audit (admin and accounting). A preview of an accounting comparison, on made-up data for now. Nothing it shows is saved.
  • My Signature in the page header: draw or upload your signature once and it prints on the POs you approve.
